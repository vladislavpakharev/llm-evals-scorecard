# Правила оценки по сторонам качества (рубрика)

## Правило оценки: понимание данных (meaning)

УСПЕХ: ответ использует правильные таблицы, поля и связи: руководитель из experiments.leader_id, участники из participation, измерения из measurements по experiment_id, людей различает по person_id, отменённый опыт не считает завершённым, не придумывает связь прибора с опытом. Ложную предпосылку, противоречащую строкам базы, замечает и исправляет.
ОШИБКА: руководитель и участник подменены друг другом; выдуманы таблица, поле или связь; люди с одинаковым именем склеены; ложная предпосылка принята как факт; назван случай, которого нет в данных.
СПОРНО: число верное, но таблицы и логика не названы и SQL нет; предпосылка вопроса допускает два прочтения; часть связей названа верно, часть не названа.

## Правило оценки: правильность расчёта (calculation)

УСПЕХ: итог совпадает с моим независимым SQL при тех же условиях; после JOIN считаются разные объекты (DISTINCT), а не строки соединения; единицы приведены (1 kg = 1000 g, F в C = (F-32)/1,8); месяц это полуинтервал [1-е число 00:00:00, 1-е следующего 00:00:00); среднее по всем записям не заменено средним из средних.
ОШИБКА: итог расходится с эталоном при однозначной постановке и расхождение показано строкой или запросом (например 31 вместо 7 из-за COUNT(*) после JOIN; 11 вместо 10 из-за включённой границы 1 августа; сложены kg и g).
СПОРНО: вопрос допускает разные условия отбора (например, брать ли suspect); результат совпал, но способа расчёта не видно; неверно выбраны записи (тогда сначала meaning, расчёт отдельно).

## Правило оценки: работа с неизвестным (missing)

УСПЕХ: ответ отличает известное от неизвестного: NULL не равен нулю, отсутствие осмотра не равно исправности, отсутствующие в базе сведения (стоимость, будущие работы, связь прибора с опытом) названы отсутствующими с указанием, чего не хватает. Если данные есть, отвечает по ним без лишнего отказа.
ОШИБКА: выдаёт число, состояние или причину, которых в базе нет (NULL как 0, нет осмотра как исправен, придуманная стоимость); либо отказывается отвечать там, где данные есть.
СПОРНО: даёт догадку с оговоркой, и непонятно, выдана ли она за результат; говорит «данных недостаточно», но не называет, каких именно.

## Правило оценки: работа с неоднозначностью (ambiguity)

УСПЕХ: если толкования вопроса дают разные ответы (одинаковые имена, «активный», «последний», руководил или участвовал), ответ уточняет вопрос или явно делит варианты и даёт результат для каждого. Если все условия заданы, отвечает сразу, без лишних уточнений.
ОШИБКА: молча выбирает одно толкование (или одного из тёзок) и выдаёт его как единственный ответ; либо в однозначном вопросе уходит в уточнения вместо ответа.
СПОРНО: выбрано одно толкование, другое упомянуто вскользь без результата; два толкования дают одинаковый ответ, поэтому неясно, была ли неоднозначность существенной.

## Правило оценки: устойчивость к перефразированию (stability)

ЕДИНИЦА: пара ответов на две формулировки одного смысла (одна модель, один этап, один контекст). Сравниваем смысл и результат, а не буквы SQL.
УСПЕХ: оба ответа дают по смыслу один результат (то же число, то же множество строк, тот же вывод); разные запросы допустимы.
ОШИБКА: результаты по смыслу различаются (например 6 и 7), хотя задача не менялась.
СПОРНО: ответы различаются только формой (округление, порядок, единицы с верным пересчётом); один из ответов сбой сервиса; нет уверенности, что перефразирование сохранило задачу.
ВАЖНО: пара может быть устойчиво неверной. Тогда stability = прошёл, а правильность оценивается отдельно (дополнительной оценкой meaning или calculation).
